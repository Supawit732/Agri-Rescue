# Agri-Rescue — UI Redesign Plan (Phase 6.12+)

> สำหรับ agent: วางไฟล์นี้ที่ `docs/UI_PLAN.md` และ mockup ทั้งหมดไว้ที่ `docs/design/mockups/*.dc.html`
> mockup เป็น HTML ที่ใช้ inline style ทั้งหมด ให้อ่านค่า สี ระยะ ขนาดตัวอักษร และโครงสร้างจากไฟล์ตรง ๆ (ไม่ต้องรันไฟล์)
> ข้อความใน `[ ]` คือข้อมูลตัวอย่าง ให้ใช้ข้อมูลจริงจาก API แทน

> ทุกข้อความใหม่ต้องอยู่ในไฟล์แปล th/en (ระบบสองภาษาจาก PR ก่อนหน้า)
> ต้องผ่าน: server test/lint/build, `mobile npm run build` (web + ios export) และทดสอบบน iPhone จริงผ่าน Expo Go
> กำหนดส่งเดโม: 1 ต.ค. — หยุดแก้โค้ดวันที่ 30 ก.ย. ถ้า PR ไหนไม่ทัน ให้ปิดด้วย config แทนการ merge งานครึ่งเดียว

## PR A — โครงหน้าจอ + ตลาด + โปรไฟล์ + เข้าสู่ระบบ
อ้างอิง: `Main`, `Filter`, `ProfileMenu`, `Profile`, `Login`

1. **แถบแท็บล่าง 4 แท็บ**: ตลาด · ขาย · คำสั่งซื้อ · แจ้งเตือน (ตัวเลขยังไม่อ่าน) — ย้ายแท็บบัญชีออก
2. **แถบบน**: โลโก้ + "ใกล้ฉัน · รัศมี X กม." ด้านซ้าย, **รูปโปรไฟล์มุมขวาบน** (ยังไม่ login = ปุ่ม "เข้าสู่ระบบ")
3. **เมนูโปรไฟล์** (dropdown/sheet จากมุมขวาบน): หัวเมนูกดไปหน้าโปรไฟล์, ร้านของฉัน, แดชบอร์ด, ร้านที่ติดตาม (PR B), รับบริจาค + ป้ายสถานะ, ติดต่อเรา (PR C), ภาษา TH/EN, ข้อกำหนด, ผู้ดูแลระบบ (เฉพาะ admin), ออกจากระบบ
4. **ตลาด**
   - ช่องค้นหา (ชื่อพืช; ชื่อร้านเพิ่มใน PR B) + ปุ่มตัวกรองพร้อมตัวเลขตัวกรองที่ใช้อยู่
   - แถบหมวดแบบเลื่อนข้าง (ใช้ crop_categories)
   - ตัวกรองแบบ bottom sheet: หมวด, ระยะทาง 5/10/15/25 กม., ช่วงราคา/กก., เวลาที่เหลือ, เรียงตาม (ด่วนสุด/ใกล้สุด/ถูกสุด) — ส่งเป็น query ไปที่ public market API (เพิ่มพารามิเตอร์ใน server + test)
   - การ์ด 2 คอลัมน์ตาม mockup: รูป, ป้ายเวลาตามความด่วน, ชื่อพืช, เกรด·ความสุก, ชื่อร้าน · ระยะทาง, ราคา/กก., เหลือ X/Y กก. + แถบคงเหลือ
5. **รูปล็อต**: ตาราง `lot_photos` (migration ใหม่), เก็บไฟล์ใน `server/uploads/` (อยู่ใน .gitignore) ย่อเป็น jpeg/webp ≤ 1MB, รูปที่ใช้ให้ AI ประเมินบันทึกเป็นรูปล็อตอัตโนมัติ, public API คืน URL รูป; ไม่มีรูปแสดงพื้นสีตามพืช + ไอคอน
6. **โปรไฟล์**: รูปโปรไฟล์ (อัปโหลดได้), สวิตช์ผู้ขาย/ผู้ซื้อ, ลิงก์ร้านของฉัน, ข้อมูลติดต่อ (เบอร์, อีเมล, LINE ID) พร้อมคำอธิบายว่าอีกฝ่ายเห็นเมื่อไร, ตำแหน่งรับของ (LocationPicker), การ์ดสถานะรับบริจาค
7. **เข้าสู่ระบบ**: ช่องเดียว "เบอร์โทร หรืออีเมล" (users.email unique NULL ได้; login ค้นได้ทั้งสองแบบ), แสดง/ซ่อนรหัสผ่าน, สลับภาษา, ลิงก์ "ดูตลาดโดยไม่เข้าสู่ระบบ"; ยังไม่มีปุ่ม LINE จนกว่า PR D
8. ย้ายทุกหน้าเดิมเข้าโครงใหม่โดยไม่เปลี่ยนการทำงาน; หน้าที่ไม่มี mockup ให้ใช้ token และ component เดียวกัน

## PR B — ร้านค้า ติดตาม และแจ้งเตือนในแอป
อ้างอิง: `Shop`, `Notifications`

1. **โปรไฟล์ร้าน**: `shops(user_id, name, avatar, cover, description)` สร้างอัตโนมัติเมื่อเปิดการขาย (ชื่อเริ่มต้นแก้ได้); public API คืนชื่อร้าน ตำบล/อำเภอ พืชที่ขายบ่อย และสถิติที่คำนวณจริง (ส่งมอบสำเร็จ, ผู้ติดตาม, กก. ที่ช่วยได้) — ห้ามคืนพิกัดหรือเบอร์
2. **หน้าร้าน**: รูปปก, ชื่อ, สถิติ, ปุ่มติดตาม/เลิกติดตาม, แท็บกำลังขาย/ขายแล้ว
3. **ค้นหาชื่อร้าน** ในช่องค้นหาของตลาด
4. **ติดตาม**: `shop_follows(user_id, shop_id)` unique; ต้อง login; หน้า "ร้านที่ติดตาม" ในเมนูโปรไฟล์
5. **แจ้งเตือนในแอป** (ยังไม่ทำ push): `notifications(user_id, type, title_key, params_json, link, read_at, created_at)` + API รายการ/อ่านแล้ว/อ่านทั้งหมด + ตัวเลขยังไม่อ่านบนแท็บ
   - เหตุการณ์: ร้านที่ติดตามลงล็อตใหม่, ล็อตถูกจอง, ผู้ขายยืนยันรับของ, ผลการตรวจคำขอรับบริจาค, ใกล้ครบกำหนดส่งรูปยืนยันบริจาค, คำตอบจากทีมงาน (PR C)
   - หน้าแจ้งเตือนตาม mockup: กรอง ทั้งหมด/ร้านที่ติดตาม/คำสั่งซื้อ, จุดยังไม่อ่าน, กดแล้วไปหน้าที่เกี่ยวข้อง
   - ข้อความเก็บเป็น key + params เพื่อแสดงตามภาษาที่เลือก
6. test: ติดตามซ้ำ, ไม่ login ติดตามไม่ได้, ลงล็อตแล้วผู้ติดตามได้ notification, ผู้ใช้อ่านได้เฉพาะของตัวเอง

## PR C — ติดต่อเรา (แบบย่อ)
อ้างอิง: `ContactUs`, `AdminInbox`

1. `support_tickets(id, user_id, topic, order_id NULL, status, reply_via, created_at, updated_at)` + `support_messages(ticket_id, sender_role, body, created_at)` + รูปแนบ ≤ 3 (ใช้ระบบเก็บไฟล์ของ PR A แบบ private ดูได้เฉพาะเจ้าของเรื่องและ admin)
2. ผู้ใช้: รายการเรื่องของฉันพร้อมสถานะ, ฟอร์มแจ้งเรื่อง (หัวข้อ, คำสั่งซื้อที่เกี่ยวข้อง, รายละเอียด ≤ 1000 ตัวอักษร, รูป, ช่องทางตอบกลับ), หน้าดูเรื่องและตอบต่อได้, กล่องเตือนเรื่อง OTP
3. admin: แท็บ "ติดต่อเรา" พร้อมตัวเลขยังไม่ตอบ, กรองสถานะ, เปิดเรื่อง, ตอบกลับ, เปลี่ยนสถานะ, ปิดเรื่อง; แสดงสถานะออเดอร์ที่เกี่ยวข้อง
4. ยังไม่ทำ: ปุ่มยกเลิกออเดอร์จากหน้านี้ และสถิติผู้ซื้อ/ผู้ขาย (บันทึกเป็นงานต่อใน PLAN_V2)
5. rate limit การสร้างเรื่อง 5 เรื่อง/ชม./ผู้ใช้
6. test: ผู้ใช้เห็นเฉพาะเรื่องของตัวเอง, คนอื่นดูรูปแนบไม่ได้, admin ตอบแล้วผู้ใช้ได้ notification

## PR D — LINE Login (ทำเมื่อ A–C merge แล้วและยังมีเวลา; ปิดได้ด้วย config)
- OAuth 2.1 + OpenID Connect ฝั่ง server: `/api/auth/line/start` (state + nonce + PKCE, app_redirect ต้องผ่าน allowlist), `/api/auth/line/callback` (ตรวจ state, แลก code, ตรวจ id_token), redirect กลับแอปด้วย one-time code อายุ 60 วินาที แล้วแลกเป็น JWT ผ่าน `/api/auth/line/exchange` (ห้ามส่ง JWT ใน URL)
- `users.line_user_id` unique; ผู้ใช้ใหม่ต้องกรอกเบอร์โทร ตำแหน่ง ขาย/ซื้อ และยอมรับข้อกำหนดก่อนใช้งาน; ผูก/ยกเลิกผูก LINE ในหน้าโปรไฟล์
- config: `LINE_CHANNEL_ID`, `LINE_CHANNEL_SECRET`, `LINE_CALLBACK_URL`, `LINE_LOGIN_ENABLED` (ค่าว่างใน .env.example; ไม่ครบ = ซ่อนปุ่ม)
- ปุ่มตามแนวทางแบรนด์ LINE ใช้โลโก้ทางการ
- `docs/LINE_LOGIN.md`: สร้าง channel, ตั้ง Cloudflare Tunnel ให้ server มี https, ค่า callback, วิธีปิดฟีเจอร์ — ห้าม commit secret หรือ URL tunnel
- test: mock LINE ทุก endpoint; state/nonce ผิด, one-time code ใช้ซ้ำ, redirect นอก allowlist, ปิดฟีเจอร์แล้ว 404
