## 1. โปรเจกต์โดยย่อ

**Agri-Rescue: Hyperlocal Surplus Produce Rescue & Group Routing**
แอปมือถือระบายผลผลิตตกเกรดหรือใกล้เสียในรัศมี 10–15 กม. ผู้ใช้หนึ่งคนเป็นได้ทั้งผู้ขาย (เกษตรกร) และผู้ซื้อ ระบบประเมินอายุการขายและราคาด่วนด้วย AI + พยากรณ์อากาศ จัดเส้นทางรับของหลายแปลงในรอบเดียว และรองรับการบริจาคให้ผู้รับที่ผ่านการยืนยัน

- งานกลุ่มวิชา Internet Programming (รวม BPDD, Database, AI) มหาวิทยาลัยเกษตรศาสตร์ วิทยาเขตศรีราชา
- **นำเสนอ + เดโมบน iPhone จริง: 1 ต.ค. 2026** (สไลด์ภาษาอังกฤษ 10 นาที + เดโม 5 นาที + Q&A)
- **หยุดแก้โค้ด: 30 ก.ย.** หลังเย็นวันที่ 27 รับเฉพาะงานแก้บั๊กเล็ก

## 4. สิ่งที่เสร็จแล้ว (อยู่บน main)

**พื้นฐาน**
- Phase 0–5: schema, domain logic (shelf-life, ราคาด่วน, haversine, routing NN + 2-opt, state machine), API, แอป
- บัญชีหลายบทบาท `can_sell` / `can_buy` / `is_admin` — **admin ซื้อขายไม่ได้** (แบ่งแยกหน้าที่)
- Login ด้วยเบอร์หรืออีเมล (ปุ่มสลับ, ใส่ขีดเบอร์อัตโนมัติ, ชิปโดเมนอีเมล); สมัครต้องมีเบอร์ อีเมลไม่บังคับ
- ระบบสองภาษา TH/EN ครบทั้งข้อความหน้าจอและข้อมูลระบบจาก server (ชื่อพืช, หมวด, ตำบล/อำเภอ, enum, ผล AI, วันที่)

**ผู้ขาย**
- ลงล็อต: พืช, แปลง, น้ำหนัก, เกรด, ความสุก (ไม่เลือกไว้ล่วงหน้า), โหมดขาย (sell / donate / sell_then_donate), กลุ่มผู้รับบริจาค, แบ่งขาย (ขั้นต่ำ/ขั้นละ), ราคาเริ่มต้น/ต่ำสุดในกรอบราคาตลาด
- AI ประเมินรูป: ความสุก, ความมั่นใจ, ตำหนิ (แยกลักษณะปกติของพืช), ตรวจว่ารูปตรงกับพืช (subject_match), fallback เมื่อใช้ไม่ได้
- อายุการขายจากพยากรณ์ 72 ชม. (ค่าเฉลี่ยกลางวัน + ความชื้น > 85%)
- ราคาอ้างอิงจาก MOC จับคู่อัตโนมัติ + ตัวแปลงหน่วย (admin ตั้งได้)
- แก้ไขล็อต (กันยืดอายุ/เพิ่มน้ำหนัก + log), ลบแบบ soft delete, ปุ่มลงประกาศติดขอบล่าง
- ยืนยันส่งมอบด้วย OTP + น้ำหนักจริง, ร้านค้า (ชื่อ, avatar, สถิติ), dashboard ผู้ขาย

**ผู้ซื้อ / ผู้เยี่ยมชม**
- ตลาดดูได้โดยไม่ login (public API ซ่อนพิกัดและข้อมูลผู้ขาย, rate limit), ค้นหาพืชหรือชื่อร้าน, ชิปหมวด, ตัวกรอง (หมวด ระยะ ราคา เวลาที่เหลือ) + เรียง (ด่วน/ใกล้/ถูก), การ์ดมีรูป
- ซ่อนแผน "ขายก่อนแล้วบริจาค" จากผู้ซื้อ (ใช้ `available_as`)
- จอง: รายละเอียดล็อต → เลือกจำนวน → **เลือกช่วงนัดรับ** → ยืนยัน → หน้าสำเร็จ
- รายละเอียดคำสั่งซื้อ: สถานะ + ขั้นถัดไป, OTP, ปุ่มโทร/LINE หลังจอง, Google Maps, ยกเลิก (ถามยืนยัน)
- **หน้าเส้นทางรับของ** รวมหลายแปลงในวันเดียว (NN + 2-opt, เคารพช่วงนัด, เปิดทั้งเส้นทางใน Google Maps, เทียบระยะที่ประหยัดได้)
- คำแนะนำหลังรับของ: ควรรับประทาน / ขายต่อ / แจกจ่ายภายใน + วิธีเก็บ + แช่เย็นยืดได้กี่วัน
- ติดตามร้าน, แจ้งเตือนในแอป (badge, กรอง, อ่านทั้งหมด, เวลาแบบสัมพัทธ์)

**บริจาค**
- ผู้รับ 3 ระดับ: volunteer (ใช้ได้ทันที 10 กก./สัปดาห์), trusted_volunteer (ส่งรูปผ่าน 5 ครั้ง, 30 กก.), verified_org (เอกสาร + admin อนุมัติ, ตามจำนวนผู้รับประโยชน์)
- ฟอร์มสมัครหลายขั้น + popup อธิบาย + ข้อกำหนด (terms_version), ขอเอกสารเพิ่ม / ถอน / เปลี่ยนประเภท, ไม่ขอบัตรประชาชน
- รูปยืนยันการแจกภายใน 48 ชม. ตรวจด้วย AI, พลาด 3 ครั้งใน 60 วันถูกระงับ

**ผู้ดูแลระบบ (Admin Console)**
- login แล้วเข้า console แยก: ภาพรวม (เริ่มด้วย "ต้องจัดการ" + 3 ตัวเลขหลัก, กราฟ 14 วัน, ตามพืช, 5 ร้าน) · ตลาด (ดูทั้งหมด, ซ่อนล็อตพร้อมเหตุผล) · งานรอจัดการ (คำขอองค์กร, ติดต่อเรา, น้ำหนักไม่ตรง, OTP ถูกล็อก, รูปยืนยันเลยกำหนด) · ข้อมูลระบบ (ราคา DIT, รายชื่อผู้ใช้)

**อื่น ๆ**
- ติดต่อเรา: รายการเรื่อง, ฟอร์ม (หัวข้อ, เลือกคำสั่งซื้อ, รายละเอียด, แนบรูป ≤ 3 แบบ private), thread ตอบกลับ, rate limit
- โปรไฟล์: รูปโปรไฟล์, สวิตช์ขาย/ซื้อ, ชื่อร้าน, ข้อมูลติดต่อ, ตำแหน่งรับของ (LocationPicker: GPS / ลิงก์ Google Maps / กรอกเอง), บันทึกแยกต่อการ์ด
- UI ตาม mockup: แถบบน + รูปโปรไฟล์มุมขวา, 4 แท็บ (ตลาด ขาย คำสั่งซื้อ แจ้งเตือน), safe area (ทดสอบบน iPhone Air), จุดกด ≥ 44 px, error รายช่องทุกฟอร์ม
- seed ใช้ชื่อสองภาษา เช่น "Somchai Farm (สวนลุงสมชาย)"

## 6. กฎที่ต้องทำตาม

**Git**
- หนึ่งงาน = หนึ่ง branch จาก main ล่าสุด = หนึ่ง PR; **เปิด draft PR ตั้งแต่ commit แรก**
- push ทุกครั้งที่ผ่าน: server test/lint/build + `check:en-api`, mobile `tsc` + `check:i18n` + `npm run build`
- **ห้าม mark ready หรือ merge PR เอง, ห้าม force-push, ห้าม rebase branch ที่ push แล้ว**
- จบงาน: อัปเดตคำอธิบาย PR และรายงาน (ทำอะไร, จำนวน test, คำสั่งที่ต้องรันบนเครื่อง, สิ่งที่ควรลองบน iPhone) แล้ว**หยุดรอ**
- ถ้างานพึ่ง PR ที่ยังไม่ merge ให้หยุดถามก่อน
- ถ้าการแก้ไฟล์ไม่สำเร็จ (string not found / หลาย match) ต้องแก้ให้เสร็จก่อนเขียนรายงาน และ `git status` ต้องสะอาด
- ห้าม commit `.env*`, API key, ไฟล์ใน uploads / private_uploads / .cache

**ฐานข้อมูล**
- ไม่ใช้ FOREIGN KEY และ VIEW (เผื่อ import เข้า phpMyAdmin ของอาจารย์) ตรวจ integrity ใน service และใส่ INDEX บนคอลัมน์อ้างอิง
- migration ใหม่ใช้เลขถัดไป **ห้ามแก้ ห้ามเปลี่ยนชื่อหรือเลข migration ที่ push แล้ว**
- query ใช้ placeholder เสมอ

**โค้ด**
- สูตรคำนวณอยู่ใน `server/src/domain` เป็น pure function มี unit test
- ข้อความทุกอย่างอยู่ในไฟล์แปล th/en; ข้อมูลระบบจาก server ต้องมีทั้งสองภาษา; ข้อมูลที่ผู้ใช้พิมพ์เองไม่ต้องแปล
- ฟอร์มใช้ `FormField` + error รายช่อง, เคารพ safe area, จุดกด ≥ 44 px
- test ใช้ mock สำหรับบริการภายนอก และ temp dir สำหรับ cache/ไฟล์
- อัปเดต `DECISIONS.md` และตารางสถานะใน `PLAN_V2.md` ทุก PR

**การสื่อสาร**: รายงานเป็นภาษาไทย กระชับ
