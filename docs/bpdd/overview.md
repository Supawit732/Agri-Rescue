# ภาพรวมระบบ (Overview)

แหล่งอ้างอิง: `README.md`, `docs/IMPLEMENTATION_PLAN.md` ข้อ 1, และพฤติกรรมจริงของ API ใน `server/src/`

## ปัญหาที่ระบบแก้

เกษตรกรรายย่อยมีผลผลิต**ตกเกรดหรือใกล้เน่าเสีย**ที่ขายในช่องทางปกติได้ยาก หากปล่อยไว้จะกลายเป็นของเสีย Agri-Rescue ช่วย**ระบายล็อตเหล่านี้ไปยังผู้รับซื้อในพื้นที่** โดย

1. ประเมินอายุการขาย (shelf-life) และ**ราคาด่วน**ของแต่ละล็อตจากความสุก อากาศที่แปลง และเกรด
2. ให้ผู้ซื้อจองล็อต (หรือรับบริจาคถ้าเป็นประเภทสงเคราะห์และล็อตเปิดรับบริจาค)
3. ให้ผู้ประสานรวมออเดอร์เป็น**รอบวิ่ง** แล้วให้คนขับยืนยันรับของด้วยน้ำหนักและส่งมอบด้วย OTP
4. บันทึกกิโลกรัมที่ช่วยได้และ CO₂e เมื่อส่งมอบสำเร็จ

## กลุ่มเป้าหมาย

| กลุ่ม | บทบาทในระบบ | หมายเหตุจากโค้ด |
|---|---|---|
| เกษตรกรรายย่อย | `farmer` | สมัครได้เอง มีแปลงและลงล็อต |
| ผู้รับซื้อท้องถิ่น | `buyer` (`vendor` / `shop` / `charity`) | รถเร่ ร้านค้า สถานสงเคราะห์ — สมัครได้เอง |
| คนขับรถส่ง | `driver` | สร้างจาก seed เท่านั้น สมัครผ่าน API ไม่ได้ |
| ผู้ประสานรอบวิ่ง | `coordinator` | สร้างจาก seed เท่านั้น สมัครผ่าน API ไม่ได้ |

แผนระบุรัศมีใช้งานประมาณ 10–15 กม. API ตลาดด่วนใช้รัศมีเริ่มต้น **15 กม.** (`GET /api/market`)

## จุดต่างจาก e-commerce ผักทั่วไป

| มิติ | e-commerce ผักทั่วไป (โดยทั่วไป) | Agri-Rescue (ตามโค้ดจริง) |
|---|---|---|
| สินค้า | สินค้าคงคลัง / เกรดมาตรฐาน | ล็อตใกล้หมดอายุหรือตกเกรด มี `expires_at` และสถานะ `expired` |
| ราคา | ราคาสินค้าคงที่หรือโปรโมชัน | ราคาด่วนคำนวณจาก freshness + เกรด (`urgentPricePerKg`) ตอนจอง |
| การจัดส่ง | คลัง → ลูกค้า | รับที่แปลงแล้วส่งผู้ซื้อในรอบเดียวกัน มีจุด `pickup` / `drop` |
| การยืนยัน | หลักฐานการชำระ / tracking | คนขับชั่งน้ำหนักตอนรับ และใช้ OTP 4 หลักตอนส่ง |
| ผลกระทบ | มักไม่มี | บันทึก `impact_logs` (กก. ที่ช่วยได้, CO₂e) หลังส่งมอบ |
| บริจาค | ไม่ใช่แกนหลัก | ผู้ซื้อ `charity` จองแบบบริจาคได้เมื่อล็อต `allow_donation = 1` |

## ขอบเขตของระบบ (In scope)

สิ่งที่ระบบ**ทำได้จริง**ในโค้ดปัจจุบัน

- ลงทะเบียน / เข้าสู่ระบบด้วยเบอร์โทรและรหัสผ่าน (JWT อายุ 7 วัน)
- เกษตรกรจัดการแปลง ลงล็อต ประเมิน shelf-life/ราคาผ่าน `/lots/estimate` (ดึงอากาศ Open-Meteo หรือใช้ค่าสำรอง)
- ผู้ซื้อดูตลาดด่วนในรัศมี จองหรือรับบริจาค ดู OTP ยกเลิกการจองที่ยังไม่เข้ารอบ
- ผู้ประสานสร้างรอบวิ่ง เลือกคนขับ ดูจุดแวะ ปลดล็อก OTP ที่ถูกล็อก
- คนขับดูรอบที่ได้รับมอบหมาย ยืนยันรับของด้วยน้ำหนัก ยืนยันส่งด้วย OTP
- Job หมดอายุล็อต `open` ที่ `expires_at` ผ่านแล้ว (ทุก 10 นาที)
- สรุปผลลัพธ์รวม (`/impact/summary`): กก. ที่ช่วยได้, CO₂e, รายได้เกษตรกร, กก. บริจาค, จำนวนล็อตที่ส่งมอบ
- แอปมือถือ Expo ครอบคลุม 4 role ตาม flow ด้านบน

## สิ่งที่อยู่นอกขอบเขต (Out of scope)

สิ่งต่อไปนี้**ไม่มีในโค้ด** จึงไม่ถือว่าเป็นความสามารถของระบบ

- ชำระเงินออนไลน์ / กระเป๋าเงิน / ใบเสร็จภาษี
- แชท แจ้งเตือน push หรือ SMS จริง (OTP เก็บในฐานและแสดงในแอปเท่านั้น)
- แผนที่นำทางแบบ turn-by-turn หรือ GPS tracking คนขับแบบเรียลไทม์
- AI ประเมินคุณภาพจากรูป (มีค่า `method = 'model'` ใน ENUM แต่การสร้างล็อตใช้ `'rule'` เท่านั้น)
- สมัครเป็นคนขับหรือผู้ประสานผ่านแอป
- ระบบคลังสินค้าหลายคลัง หรือขายผลผลิตเกรดพรีเมียมเป็นช่องทางหลัก
- แอดมินแบ็คออฟฟิศแยกต่างหาก
- FOREIGN KEY / VIEW ในฐานข้อมูล (ถูกห้ามโดยข้อจำกัดของวิชา — ดู [erd.md](erd.md))
