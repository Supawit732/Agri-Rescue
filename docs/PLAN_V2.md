## เป้าหมายของ v2

เปลี่ยนจาก "ระบบที่มีคนขับและผู้ประสาน" เป็น **ตลาดระบายผลผลิตระดับชุมชน** ที่
- ใครก็ดูสินค้าได้โดยไม่ต้อง login
- ผู้ใช้หนึ่งคนเป็นได้ทั้งผู้ขายและผู้ซื้อ
- ผู้ซื้อมารับเองตามเส้นทางที่ระบบจัดให้ หรือรับทางพัสดุสำหรับล็อตที่ยังมีเวลาพอ
- เงินถูกพักไว้ (escrow แบบ sandbox) จนกว่าผู้ซื้อยอมรับของ
- ระบบตัดสินใจแทนผู้ประสาน เหลือผู้ดูแลไว้จัดการกรณีผิดปกติเท่านั้น

## หลักที่ต้องรักษา
- ข้อมูลเดิมและ test เดิมต้องไม่พัง; ย้ายข้อมูลด้วย migration ใหม่เท่านั้น ห้ามแก้ migration เก่า
- การคำนวณทั้งหมดอยู่ใน `server/src/domain` เป็น pure function มี unit test
- ทุก state machine ใหม่ (order, payment, dispute) มีฟังก์ชัน transition เดียวที่ throw เมื่อผิด
- ผู้ที่ยังไม่ login ห้ามเห็น: พิกัดแปลง, ชื่อ-เบอร์-LINE ของผู้ขาย

## 6.1 บัญชีผู้ใช้แบบหลายบทบาท
- migration: `users.can_sell`, `users.can_buy` (BOOL), `users.is_admin` (BOOL), `users.line_id` NULL; `buyer_profiles(user_id, buyer_type)` ย้ายจาก `users.buyer_type`
- ย้ายข้อมูลเดิม: farmer → can_sell; buyer → can_buy; coordinator → is_admin; driver → can_buy
- สมัคร: เลือก "ขาย", "ซื้อ" หรือทั้งคู่; เปิดอีกบทบาทภายหลังได้จากหน้าโปรไฟล์ (การเป็น charity ต้องให้ผู้ดูแลอนุมัติ)
- JWT เก็บ capabilities; `requireRole` เปลี่ยนเป็น `requireCapability('sell' | 'buy' | 'admin')`
- ห้ามจองล็อตของตัวเอง → 403
- แอป: ปุ่มสลับโหมด "โหมดขาย / โหมดซื้อ" ที่ header; ซ่อนหน้าคนขับและผู้ประสานออกจากเมนู (**ลบโค้ดใน 6.11**)
- **Done when:** ผู้ใช้คนเดียวลงล็อตและจองล็อตของคนอื่นได้, จองของตัวเองได้ 403, test เดิมผ่าน

## 6.1b การยืนยันผู้รับบริจาค
- `donor_tier`: `volunteer` (10 กก./สัปดาห์ เปิดจากโปรไฟล์ทันที) → `trusted_volunteer` (เลื่อนอัตโนมัติเมื่อรูปยืนยัน `subject_match` ครบ 5 ครั้ง, 30 กก./สัปดาห์) → `verified_org` (admin อนุมัติ, เพดาน = ผู้รับประโยชน์ × 0.5 กก./สัปดาห์); ค่า config ใน DECISIONS
- สมัครองค์กร: ฟอร์ม + เอกสาร (pdf/jpg/png ≤ 5MB, รวมสูงสุด 10 ไฟล์) ใน `server/private_uploads/` (ไม่ static; ดาวน์โหลดเฉพาะ admin); ห้ามเก็บบัตรประชาชน
- สถานะคำขอ: `pending → approved | rejected | needs_more_info`; `needs_more_info → pending` เมื่อส่งเอกสารเพิ่ม; admin ต้องกรอกเหตุผลทุกครั้งที่ปฏิเสธ/ขอเอกสารเพิ่ม; เก็บประวัติใน `org_review_logs`
- `harvest_lots.donation_audience` (`verified_org_only` | `all_donors`, ค่าเริ่มต้น `verified_org_only`); เกษตรกรเลือกเมื่อติ๊กยินดีบริจาค
- ขอรับบริจาคได้เฉพาะเมื่อล็อตเปิดรับบริจาค, audience ตรง tier ที่อนุมัติแล้ว, ไม่ถูกระงับ, และไม่เกินเพดานสัปดาห์ — ผู้สมัครองค์กรที่ยังรออนุมัติ / สถานะ draft ไม่มีสิทธิ์รับบริจาค
- ตลาด: แยกปุ่มซื้อ/ขอรับบริจาค, ป้ายสิทธิ์, ยืนยันก่อนจอง, แสดงเหตุผลเมื่อไม่มีสิทธิ์
- หลังรับของ: ส่งรูปยืนยันภายใน 48 ชม. (vision `subject_match`); พลาด/ไม่ผ่าน 3 ครั้งใน 60 วัน → ระงับจนกว่า admin ปลด; expire job ตรวจกำหนด
- บัญชี charity ที่อนุมัติแล้ว ย้ายเป็น `verified_org`
- **Done when:** test เพดาน, เลื่อนระดับ, audience, ระงับ/ปลด, pending org/volunteer/suspended → 403, needs_more_info→resubmit, reject ไม่มีเหตุผล → 400, ดาวน์โหลดเอกสาร 403 สำหรับ non-admin, mock vision ทุกกรณี

## 6.1c ราคาอ้างอิง DIT / MOC และการจับคู่สินค้า
- ดึงราคาจาก API กรมการค้าภายใน (MOC) เก็บใน `crop_reference_prices`; จับคู่พืชกับรหัสสินค้าอัตโนมัติ (หมวด, กรองแปรรูป, หน่วยจาก price response) ลองใหม่รายชั่วโมงเมื่อยังไม่มีราคาวันนี้; อ้างอิงได้ไม่เกิน 30 วัน
- หน้า admin DIT: สถานะอัตโนมัติ, ชื่อสินค้าที่จับคู่, เหตุผลเมื่อไม่มีราคา, ตัวแปลงหน่วย (เช่น 1 หวี = X กก.) ในขั้นสูง
- เมื่อ API ล่ม ใช้ราคาประมาณของพืชต่อไปได้ตามปกติ
- **Done when:** test จับคู่/retry/หน่วย/ราคาประมาณเมื่อ API error

## 6.1d ข้อผิดพลาดรายช่อง + ฟอร์มผู้รับบริจาคแบบเป็นทางการ
- component กลาง `FormField` / `TextField` / `ChipGroup` / `FileField`: กรอบแดง + ข้อความไทยใต้ช่อง + ไอคอน; ตรวจตอน blur และตอนส่ง; ส่งแล้วผิดเลื่อนไปช่องแรกที่ผิด
- server คืน `{ error: { code, message, fields } }` จาก zod ทุก endpoint ที่รับฟอร์ม; แอปแสดงที่ช่องนั้น
- ใช้กับสมัคร, login, ลงล็อต, LocationPicker, โปรไฟล์, ฟอร์มผู้รับบริจาค, admin
- สมัครรับบริจาค: popup สรุปก่อนเลือกประเภท, สถานะ `draft` กรอกทีหลังได้ (ซื้อได้ แต่รับบริจาคไม่ได้จนกว่าบุคคลส่งครบ / องค์กรอนุมัติ)
- หน้า `/terms/donor` (ร่างยังไม่ผ่านตรวจทางกฎหมาย); ต้องยอมรับ `terms_version` ก่อนส่ง; เปลี่ยนเวอร์ชันต้องยอมรับใหม่
- ฟอร์มหลายขั้น + แถบความคืบหน้า + บันทึกร่าง: บุคคล (จิตอาสา) และองค์กร (เอกสารแยกประเภท, รูปสถานที่)
- admin: ข้อมูลเป็นหมวด, checklist ใน `org_review_logs`, อนุมัติ / ขอข้อมูลเพิ่ม (ระบุช่อง) / ปฏิเสธ; ผู้สมัครเห็นช่องที่ต้องแก้เป็นกรอบแดง
- **Done when:** test รูปแบบ `fields` จาก server, draft บล็อกบริจาค, บังคับ terms ตอนส่ง, checklist log

## 6.2 หน้าแรกดูสินค้าแบบไม่ต้อง login
- เก็บรูปล็อต: `lot_photos(id, lot_id, path, created_at)` เก็บไฟล์ใน `server/uploads/` (ไม่ commit), เสิร์ฟผ่าน `/uploads/...`, jpeg/webp ไม่เกิน 1MB หลังย่อ; **รูปจากการประเมิน AI บันทึกเป็นรูปล็อตอัตโนมัติ**
- `GET /api/public/market?lat=&lng=&radius_km=&crop_id=&sort=` ไม่ต้อง login, rate limit 60/นาที/IP
  - คืน: รูป, พืช, น้ำหนัก, เกรด, ความสุก, **ป้าย `sale_mode`**, **ราคาปัจจุบัน + ราคาตลาดอ้างอิง** (ล็อตบริจาค/`donate` ไม่แสดงราคา), เวลาที่เหลือ, ระยะทางปัดเป็น 0.5 กม., ชื่อตำบล/อำเภอ, วิธีรับที่รองรับ, **สิทธิ์รับบริจาคของผู้ดู** (ถ้า login)
  - ไม่คืนพิกัด ชื่อผู้ขาย หรือข้อมูลติดต่อ
- `GET /api/public/lots/:id` รายละเอียดล็อตแบบเดียวกัน
- แอป: route เริ่มต้นเป็นหน้า "ตลาด" (grid การ์ดสินค้ามีรูป) ขอตำแหน่งเพื่อคำนวณระยะ ถ้าไม่ให้ใช้ LocationPicker หรือแสดงทั้งหมดเรียงตามเวลาที่เหลือ; มีตัวกรองพืชและเรียงตาม ใกล้สุด / ด่วนสุด / ถูกสุด
- กดจองหรือกด "ลงขาย" ตอนยังไม่ login → ไปหน้า login แล้วกลับมาที่เดิม
- **Done when:** เปิดแอปโดยไม่ login เห็นสินค้าพร้อมรูปและป้าย sale_mode, ล็อต donate ไม่มีราคา, response ของ public API ไม่มีพิกัดหรือข้อมูลผู้ขาย (มี test ยืนยัน)

## 6.3 รายการพืชที่ขยายได้
- migration: `crop_categories(id, name_th, default_shelf_days, parcel_allowed)` เช่น ผักใบ 2 วัน/ไม่ส่งพัสดุ, ผลไม้เมืองร้อน 5 วัน, ผลไม้เปลือกแข็ง/ส้ม 14 วัน, หัว/ราก 21 วัน, สมุนไพร 4 วัน
- `crops` เพิ่ม `category_id`, `parcel_allowed`, `storage_tip_th`, `fridge_ok` (BOOL), `fridge_extra_days`, `status ENUM('approved','pending')`, `created_by` NULL, **`normal_features_th` / `defect_examples_th` จากค่าเริ่มต้นของหมวด**
- seed เพิ่มพืชที่พบบ่อยในไทยให้ได้ประมาณ 30 ชนิด พร้อมคำแนะนำการเก็บ; ค่าทุกตัวเป็นค่าประมาณที่บันทึกแหล่งอ้างอิงไว้ใน `docs/crop-sources.md` และให้ผู้ใช้ตรวจก่อน merge
- เกษตรกรเพิ่มพืชที่ไม่มีได้: ชื่อ + หมวด + ราคาตลาดปกติ/กก. → สร้าง crop `status = pending` ใช้ค่าเริ่มต้นของหมวดทันที การ์ดแสดงป้าย "พืชใหม่ รอตรวจ"; **จับคู่ DIT อัตโนมัติแบบเดียวกับพืชเดิม**; **ราคาตลาดที่เกษตรกรกรอกเป็นฐานกรอบ start/floor จนกว่าจะมีราคา DIT**
- ผู้ดูแลอนุมัติ/แก้ค่า/รวมกับพืชที่มีอยู่ได้ในหน้าผู้ดูแล
- แอป: chip พืชเปลี่ยนเป็นช่องค้นหา + รายการพืชที่ใช้บ่อยของผู้ใช้ + ปุ่ม "เพิ่มพืชใหม่"
- AI ประเมินรูปใช้ชื่อพืชจริงของล็อต (รวมพืชใหม่) ใน prompt
- **Done when:** ลงล็อตพืชใหม่ได้โดยใช้ค่าหมวดและ features เริ่มต้น, อนุมัติแล้วค่าอัปเดต, test shelf-life ของพืช pending

## 6.4 วิธีรับของ: มารับเอง หรือ ส่งพัสดุ
- `harvest_lots.fulfillment_options` (pickup, parcel); parcel เลือกได้เฉพาะเมื่อ `crop.parcel_allowed` และเหลือเวลา > 72 ชม. ตอนลงขาย **และ** ตอนจอง
- **มารับเอง**
  - ตอนจองเลือกช่วงเวลามารับ (ต้องจบก่อนล็อตหมดอายุอย่างน้อย 2 ชม.)
  - หน้า "เส้นทางรับของวันนี้" ของผู้ซื้อ: รวมล็อตที่ชำระแล้วของวันนั้น จัดเส้นทางจากตำแหน่งผู้ซื้อด้วย `RouteSolver` เดิม เปิดแต่ละจุดใน Google Maps ได้
  - ส่งมอบ: ผู้ซื้อตรวจของที่แปลง พอใจแล้วแสดง OTP → **ผู้ขายกรอก OTP และน้ำหนักจริง** = ผู้ซื้อยอมรับของ; น้ำหนักต่างเกิน 10% ต้องให้ผู้ซื้อกดยอมรับน้ำหนักใหม่ก่อน และปรับยอดเงินตามจริงด้วย**ราคาที่ล็อกไว้ตอนจอง** (คืนส่วนต่าง)
  - ผู้ซื้อปฏิเสธของที่แปลงได้ (เลือกเหตุผล + รูป) → เปิดข้อพิพาททันที
- **ส่งพัสดุ**
  - ผู้ซื้อกรอกที่อยู่จัดส่งตอนจอง; ค่าส่งเป็นอัตราคงที่ต่อ กก. ตั้งใน config (บันทึกใน DECISIONS)
  - ผู้ขายกรอกเลขพัสดุไปรษณีย์ไทย → แอปแสดงลิงก์หน้าติดตามพัสดุ (ไม่เรียก API)
  - ผู้ซื้อกด "ได้รับของแล้ว" หรือเปิดข้อพิพาทภายใน 24 ชม.; ไม่ทำอะไรเลย ระบบถือว่ายอมรับเมื่อครบ 5 วันหลังผู้ขายกรอกเลขพัสดุ
- **ออเดอร์บริจาค: รับเองเท่านั้น (ไม่ส่งพัสดุ)**
- ย้าย `batches`/`route_stops` ให้ผูกกับผู้ซื้อ (`owner_user_id`) แทนคนขับ ผ่าน migration (ลบโค้ด/หน้าจอคนขับใน 6.11)
- **Done when:** flow test มารับเอง และส่งพัสดุ ผ่านครบ, parcel ถูกปฏิเสธเมื่อเวลาเหลือไม่พอหรือเป็นออเดอร์บริจาค

## 6.5 Escrow (sandbox)
- `PaymentProvider` interface: `createCharge`, `getStatus`, `refund`, `payout`; ทำ `MockPaymentProvider` (ค่าเริ่มต้น) และเผื่อไว้สำหรับ Opn/Omise test mode ผ่าน env ภายหลัง
- `payments(id, order_id, amount, status, provider, provider_ref, deadline_at, paid_at, released_at, refunded_amount)`
- สถานะ: `pending → paid_held → released | refunded | partially_refunded`, `pending → expired`
- `ledger_entries(id, order_id, account, debit, credit, memo, created_at)` บัญชี: buyer_cash, escrow_hold, seller_payable, refunds — ทุกการเปลี่ยนสถานะเงินบันทึกคู่ debit/credit ที่สมดุล (มี test ยืนยันยอดรวมเป็นศูนย์)
- เวลาชำระ (pure function ใน domain): `clamp(5% ของชั่วโมงที่เหลือ, 15 นาที, 2 ชม.)` และไม่เกินเวลาเริ่มช่วงนัดรับ
- **ออเดอร์บริจาคไม่มี payment** แต่มีกำหนดยืนยันช่วงนัดรับ; **ราคาที่ล็อกตอนจองมาจากสูตรที่มี floor**
- แอป: หลังจองแสดง QR PromptPay จำลอง + ปุ่ม "จำลองการชำระ" (เฉพาะ sandbox) + นาฬิกานับถอยหลัง (ข้ามสำหรับบริจาค)
- ปล่อยเงินให้ผู้ขายเมื่อผู้ซื้อยอมรับของ (6.4); คืนเงินเมื่อยกเลิก/ข้อพิพาท
- หน้า "กระเป๋าเงิน" ของผู้ขาย: ยอดรอรับ, ยอดได้รับแล้ว, รายการย้อนหลัง
- **Done when:** ทุก transition ของ payment มี test, ledger สมดุลทุกกรณี, หมดเวลาชำระแล้วล็อตกลับเป็น open, ออเดอร์บริจาคไม่มีแถว payment

## 6.6 ความน่าเชื่อถือของการจอง
- ยกเลิกก่อนชำระ: ฟรี; หลังชำระก่อนนัดรับ: คืนเงินเต็ม แต่นับเป็น "ยกเลิกช้า"; ไม่มารับตามนัด (เลยช่วงนัด + 1 ชม.): คืนเงินเต็ม นับเป็น "ไม่มาตามนัด" และล็อตกลับเข้าตลาด
- ผู้ขายยกเลิกหลังรับเงิน: คืนเงินผู้ซื้อเต็ม นับสถิติฝั่งผู้ขาย
- `waitlist(lot_id, user_id, created_at)` ต่อคิวล็อตที่ถูกจองแล้วได้; ล็อตว่างเมื่อไร เสนอคนแรกในคิวก่อน 15 นาที แล้วค่อยเปิดให้ทุกคน
- **การสลับ `sell_then_donate` ต้องเคารพ waitlist** (คิวผู้ซื้อได้ก่อนถ้ายังมีเวลา)
- สถิติผู้ใช้ (คำนวณจาก orders): รับสำเร็จ, ยกเลิกช้า, ไม่มาตามนัด แสดงบนการ์ดคำสั่งซื้อฝั่งผู้ขาย; **แยกสถิติ "ไม่มาตามนัด" ออกจากการนับรูปยืนยันบริจาคของ 6.1b**
- ไม่มาตามนัดครบ 3 ครั้งใน 30 วัน → จองได้ครั้งละ 1 ล็อต (บันทึกใน DECISIONS)
- expire job เดิมขยายให้ตรวจ payment หมดเวลา และนัดรับที่เลยเวลา
- **Done when:** test ครบทุกเส้นทางการยกเลิก, waitlist, sell_then_donate เคารพคิว, และ job

## 6.7 ปุ่มติดต่อ
- หลังชำระเงินแล้วเท่านั้น ทั้งสองฝ่ายเห็นปุ่ม "โทร" (`tel:`) และ "LINE" (`https://line.me/ti/p/~{line_id}`) ถ้ามี (ออเดอร์บริจาค: หลังยืนยันนัดรับ)
- **Done when:** test ว่า API ไม่คืนเบอร์/LINE ก่อนชำระ/ก่อนยืนยันนัด

## 6.8 ข้อพิพาท
- `disputes(id, order_id, opened_by, reason, status, ai_summary, resolution, refund_amount, decided_by, created_at, decided_at)` + `dispute_photos`
- สถานะ: `open → ai_reviewed → resolved_refund | resolved_partial | resolved_release`
- ผู้ซื้อเปิดได้: ตอนปฏิเสธที่แปลง หรือภายใน 24 ชม. หลังได้รับพัสดุ; ต้องแนบรูปอย่างน้อย 1 รูป
- AI (ใช้ vision client เดิม) เทียบรูปล็อตกับรูปหลักฐาน → สรุปความต่างเป็นภาษาไทย + ระดับความรุนแรง; **AI ไม่คืนเงินเอง**
- หน้าผู้ดูแล: รายการข้อพิพาท, รูปทั้งสองฝั่ง, สรุป AI, ปุ่มตัดสิน (คืนเต็ม / คืนบางส่วน / โอนให้ผู้ขาย) + เหตุผล
- ระหว่างข้อพิพาท เงินอยู่ใน escrow
- **ออเดอร์บริจาคไม่มีการคืนเงิน** — ข้อพิพาทเป็นการรายงานคุณภาพ มีผลต่อสถิติผู้ขาย
- **Done when:** flow test ทั้งสามผลตัดสิน (ซื้อ), รายงานคุณภาพบริจาค, ledger สมดุล, AI ล้มเหลวแล้วยังตัดสินได้

## 6.9 คำแนะนำหลังรับของ
- เมื่อผู้ซื้อยอมรับของ แสดง "ควรขาย/รับประทานภายใน X (ถึงวัน-เวลา)" จาก `expires_at` ของล็อต
- แสดงวิธีเก็บจาก `crop.storage_tip_th`; ถ้า `fridge_ok` แสดงเวลาที่ยืดได้เมื่อแช่เย็น
- ผู้ซื้อประเภทรถเร่/ร้านค้า แสดงเป็น "ควรขายต่อภายใน" + แนะนำลดราคาเมื่อเหลือน้อยกว่า 12 ชม.
- **ผู้รับบริจาคเห็นเป็น "ควรแจกจ่ายภายใน"**
- เก็บไว้ในหน้า "ของที่ได้รับ" ดูย้อนหลังได้
- **Done when:** คำนวณใน domain มี test, ข้อความไม่ได้มาจาก AI สร้างสด
