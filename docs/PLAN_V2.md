เปลี่ยนจากระบบรอบวิ่งกลางเป็น **ตลาดระบายผลผลิตระดับชุมชน** ที่
- ใครก็ดูสินค้าได้โดยไม่ต้อง login
- ผู้ใช้หนึ่งคนเป็นได้ทั้งผู้ขายและผู้ซื้อ
- ผู้ซื้อมารับเองตามเส้นทางที่ระบบจัดให้ หรือรับทางพัสดุสำหรับล็อตที่ยังมีเวลาพอ

- ระบบตัดสินใจแทนผู้ประสาน เหลือผู้ดูแลไว้จัดการกรณีผิดปกติเท่านั้น

- ข้อมูลเดิมและ test เดิมต้องไม่พัง; ย้ายข้อมูลด้วย migration ใหม่เท่านั้น ห้ามแก้ migration เก่า; **ห้ามเปลี่ยนชื่อ/เลข migration ที่เคย push แล้ว** (ดู Conventions ใน `IMPLEMENTATION_PLAN.md` และ D021)

## 6.1 บัญชีผู้ใช้แบบหลายบทบาท
- migration: `users.can_sell`, `users.can_buy` (BOOL), `users.is_admin` (BOOL), `users.line_id` NULL; `buyer_profiles(user_id, buyer_type)` ย้ายจาก `users.buyer_type`
- ย้ายข้อมูลเดิมตาม migration (ขาย/ซื้อ/ผู้ดูแล); JWT เก็บ capabilities; `requireCapability('sell' | 'buy' | 'admin')`
- สมัคร: เลือก "ขาย", "ซื้อ" หรือทั้งคู่; เปิดอีกบทบาทภายหลังได้จากแท็บบัญชี/โปรไฟล์ (การเป็น charity ต้องให้ผู้ดูแลอนุมัติ)
- ห้ามจองล็อตของตัวเอง → 403
- นำทางหลัก: แท็บตลาด/ขาย/คำสั่งซื้อ/แจ้งเตือน/บัญชี (ทำครบใน 6.1f) — **ไม่มีปุ่มสลับโหมดขาย/ซื้อ**
- **Done when:** ผู้ใช้คนเดียวลงล็อตและจองล็อตของคนอื่นได้, จองของตัวเองได้ 403, test เดิมผ่าน

## 6.1b การยืนยันผู้รับบริจาค
- `donor_tier`: `volunteer` (10 กก./สัปดาห์ เปิดจากโปรไฟล์ทันที) → `trusted_volunteer` (เลื่อนอัตโนมัติเมื่อรูปยืนยัน `subject_match` ครบ 5 ครั้ง, 30 กก./สัปดาห์) → `verified_org` (admin อนุมัติ, เพดาน = ผู้รับประโยชน์ × 0.5 กก./สัปดาห์); ค่า config ใน DECISIONS
- สมัครองค์กร: ฟอร์ม + เอกสาร (pdf/jpg/png ≤ 5MB, รวมสูงสุด 10 ไฟล์) ใน `server/private_uploads/` (ไม่ static; ดาวน์โหลดเฉพาะ admin); ห้ามเก็บบัตรประชาชน
- สถานะคำขอ: `pending → approved | rejected | needs_more_info`; `needs_more_info → pending` เมื่อส่งเอกสารเพิ่ม; admin ต้องกรอกเหตุผลทุกครั้งที่ปฏิเสธ/ขอเอกสารเพิ่ม; เก็บประวัติใน `org_review_logs`
- `harvest_lots.donation_audience` (`verified_org_only` | `all_donors`, ค่าเริ่มต้น `verified_org_only`); เกษตรกรเลือกเมื่อโหมดมีบริจาค
- ขอรับบริจาคได้เฉพาะเมื่อล็อตเปิดรับบริจาค (`available_as` มี `donate`), audience ตรง tier ที่อนุมัติแล้ว, ไม่ถูกระงับ, และไม่เกินเพดานสัปดาห์ — ผู้สมัครองค์กรที่ยังรออนุมัติ / สถานะ draft ไม่มีสิทธิ์รับบริจาค
- ตลาด: แยกปุ่มซื้อ/ขอรับบริจาคตาม `available_as`, ป้ายสิทธิ์, ยืนยันก่อนจอง, แสดงเหตุผลเมื่อไม่มีสิทธิ์
- หลังรับของ: ส่งรูปยืนยันภายใน 48 ชม. (vision `subject_match`); พลาด/ไม่ผ่าน 3 ครั้งใน 60 วัน → ระงับจนกว่า admin ปลด; expire job ตรวจกำหนด
- บัญชี charity ที่อนุมัติแล้ว ย้ายเป็น `verified_org`
- **Done when:** test เพดาน, เลื่อนระดับ, audience, ระงับ/ปลด, pending org/volunteer/suspended → 403, needs_more_info→resubmit, reject ไม่มีเหตุผล → 400, ดาวน์โหลดเอกสาร 403 สำหรับ non-admin, mock vision ทุกกรณี

## 6.1c ราคาอ้างอิง · ราคาผู้ขาย · โหมดขาย · AI ตำหนิ · แก้ไขล็อต
- ดึงราคาจาก MOC Open Data (`gis-product-prices` / `gis-products`); ราคาตลาด = ค่ากลาง `(price_min+price_max)/2` ของวันล่าสุด; ใช้ขายส่งเป็นหลัก; จับคู่อัตโนมัติ (หมวด, กรองแปรรูป, หน่วยจาก price response); ลองใหม่รายชั่วโมง; อ้างอิงได้ไม่เกิน 30 วัน
- `crops.dit_product_code`, `dit_unit`, `dit_unit_to_kg`; ถ้าหน่วยไม่ใช่บาท/กก. ใช้ได้เมื่อ admin ใส่ตัวแปลงเท่านั้น; `crop_reference_prices` เก็บ wholesale/retail, product_code, unit, source_url, date
- ไม่มีข้อมูลวันนี้ → ใช้ล่าสุด ≤ 30 วัน; ไม่มีเลย → `market_price_per_kg` + ป้าย "ราคาประมาณ"; admin DIT แสดงสถานะอัตโนมัติ + ตัวแปลงหน่วยในขั้นสูง
- ผู้ขายกำหนด `start_price_per_kg` / `floor_price_per_kg`; สูตร `max(floor, round(start×(0.3+0.7×freshness)))`; กรอบและ % ใน DECISIONS
- `sale_mode` (`sell` | `donate` | `sell_then_donate`) เป็นแหล่งความจริงของโหมด; job เปิดบริจาคเมื่อ `sell_then_donate` เหลือ &lt; 12 ชม. — **ผู้ซื้อเห็นผ่าน `available_as` เท่านั้น** (ดู 6.1f / D022)
- `crops.normal_features_th` / `defect_examples_th` ใส่ใน vision prompt; ห้ามนับลักษณะปกติเป็นตำหนิ
- `PATCH /lots/:id` เจ้าของ + สถานะยังมีคงเหลือ (`open` / `partially_reserved`) เท่านั้น; ลดน้ำหนักได้แต่ไม่ต่ำกว่ายอดจอง (6.1e); `lot_edit_logs`; แอปมีปุ่มแก้ไข
- **Done when:** mock MOC ใน test, หน่วยนอก กก. ต้องมีตัวแปลง, ราคานอกกรอบ 400, คนอื่นแก้ 403, ยืดอายุ/เพิ่มน้ำหนักไม่ได้, prompt มี features ของพืช

## 6.1d ข้อผิดพลาดรายช่อง + ฟอร์มผู้รับบริจาคแบบเป็นทางการ
- component กลาง `FormField` / `TextField` / `ChipGroup` / `FileField`: กรอบแดง + ข้อความไทยใต้ช่อง + ไอคอน; ตรวจตอน blur และตอนส่ง; ส่งแล้วผิดเลื่อนไปช่องแรกที่ผิด
- server คืน `{ error: { code, message, fields } }` จาก zod ทุก endpoint ที่รับฟอร์ม; แอปแสดงที่ช่องนั้น
- ใช้กับสมัคร, login, ลงล็อต/แก้ไขล็อต (น้ำหนัก, ราคาเริ่มต้น/ต่ำสุด, sale_mode, ความสุก), LocationPicker, โปรไฟล์, ฟอร์มผู้รับบริจาค, admin (รวมตัวแปลงหน่วย DIT)
- สมัครรับบริจาค: popup สรุปก่อนเลือกประเภท, สถานะ `draft` กรอกทีหลังได้ (ซื้อได้ แต่รับบริจาคไม่ได้จนกว่าบุคคลส่งครบ / องค์กรอนุมัติ)
- หน้า `/terms/donor` (ร่างยังไม่ผ่านตรวจทางกฎหมาย); ต้องยอมรับ `terms_version` ก่อนส่ง; เปลี่ยนเวอร์ชันต้องยอมรับใหม่
- ฟอร์มหลายขั้น + แถบความคืบหน้า + บันทึกร่าง: บุคคล (จิตอาสา) และองค์กร (เอกสารแยกประเภท, รูปสถานที่)
- admin: ข้อมูลเป็นหมวด, checklist ใน `org_review_logs`, อนุมัติ / ขอข้อมูลเพิ่ม (ระบุช่อง) / ปฏิเสธ; ผู้สมัครเห็นช่องที่ต้องแก้เป็นกรอบแดง
- **Done when:** test รูปแบบ `fields` จาก server, draft บล็อกบริจาค, บังคับ terms ตอนส่ง, checklist log

## 6.1e การแบ่งขายล็อต
- `harvest_lots.split_allowed` (ดีฟอลต์ true), `min_order_kg` / `order_step_kg` (ดีฟอลต์ 1); ลงล็อตเลือกแบ่งขายได้หรือขายยกล็อต; แก้ล็อตลดน้ำหนักได้แต่ไม่ต่ำกว่ายอดจอง
- `orders.quantity_kg`; หนึ่งล็อตหลายออเดอร์; คงเหลือ = `weight_kg − Σ quantity_kg` ของออเดอร์ที่ไม่ยกเลิก (domain + service); จองด้วย transaction + `FOR UPDATE`
- กฎจำนวน: ≥ `min_order_kg`, ตรง `order_step_kg`, ≤ คงเหลือ; ยกล็อตต้องจองเต็มคงเหลือ; เศษ &lt; ขั้นต่ำจองทั้งเศษได้; ราคาล็อกต่อออเดอร์ตอนจอง
- สถานะล็อต: `open → partially_reserved → fully_reserved`; ยกเลิกคืนคงเหลือ; `sell_then_donate` เปิดบริจาคเฉพาะคงเหลือ; ผู้รับบริจาคขอรับบางส่วนได้ไม่เกินเพดาน 6.1b
- ส่งมอบ: `weight_flag` / น้ำหนักจริงต่อออเดอร์เทียบ `quantity_kg`; `impact_logs` ต่อออเดอร์; ล็อต `delivered` เมื่อทุกออเดอร์ส่งแล้วและไม่มีคงเหลือ
- ตลาด: แสดงเหลือ X/Y กก. + ขั้นต่ำ; จองมี +/- ตาม step + error รายช่อง; ล็อตของฉันแสดงรายการผู้จอง
- **Done when:** จองพร้อมกันเกินคงเหลือ → 409, ขั้นต่ำ/step/ยกล็อต/เศษท้าย, ยกเลิกคืนคงเหลือ, sell_then_donate เฉพาะคงเหลือ, ลดน้ำหนักต่ำกว่าจอง → 400

## 6.1f โครงนำทาง
- แท็บหลัก (expo-router `Tabs`, ไอคอน `@expo/vector-icons` / Ionicons): **ตลาด** (เริ่มต้น) / **ขาย** / **คำสั่งซื้อ** / **แจ้งเตือน** / **บัญชี**
- ยังไม่ login: เปิด `(tabs)/*` ได้; แท็บ/ปุ่มที่ต้องสิทธิ์แสดงหน้าชวนเข้าสู่ระบบ (`LoginPrompt` → `/login?returnTo=…`) ไม่เด้งออกจากแท็บ
- แท็บขาย: ถ้า `!user.can_sell` แสดงอธิบาย + ปุ่มเปิดการขาย; แท็บคำสั่งซื้อ/การซื้อ: ถ้า `!user` หรือ `!can_buy` แสดงชวน login / เปิดการซื้อ
- ไม่ใช้ hamburger; ไม่มีปุ่มสลับโหมดขาย/ซื้อ
- เว็บจอกว้าง **≥ 900px**: เมนูด้านซ้ายแทนแถบล่าง; จอแคบใช้ bottom tabs
- หน้าไม่ใช่แท็บ: `StackHeader` / `SubScreen`; URL แยกทุกหน้า; back ไปหน้าแม่ที่สมเหตุสมผล
- สำเร็จหลังลงล็อต/จอง: หน้า success + CTA; ฟอร์มที่ยังไม่บันทึกถามยืนยันก่อนออก; empty state มีข้อความ + CTA
- แท็บบัญชี: โปรไฟล์, เปิดการขาย/ซื้อ, สมัครรับบริจาค+สถานะ, ผลลัพธ์, ข้อกำหนด, ออกจากระบบ; `is_admin` → ผู้ดูแลระบบ
- การจอง: `/lots/:id` → `/lots/:id/confirm` → `/lots/:id/success`; `/orders/:id` (รายละเอียด + OTP ฝั่งผู้ซื้อ; ฝั่งผู้ขายลิงก์จากล็อตของฉัน — ยืนยัน OTP+น้ำหนักจริงทำใน 6.4)
- **ซ่อนแผนบริจาค:** `available_as` แทน `sale_mode` ดิบ (D022); ปุ่ม UI `paddingHorizontal ≥ 20`, `minWidth ≥ 160`, `CtaStack` หน้าว่าง/ชวน login
- **Done when:** สลับ 5 แท็บได้โดยไม่ login, จองครบ flow แยกหน้า, จอกว้างมี side nav

## 6.2 หน้าแรกดูสินค้าแบบไม่ต้อง login
> ส่วนที่ 6.1f ทำแล้ว: route เริ่มที่แท็บตลาด `/`, flow จอง `/lots/:id`…, `available_as`, `returnTo` หลัง login — **ยังต้อง login เพื่อดูรายการตลาด** และยังไม่มี public API / รูปล็อต / ตัวกรอง

- เก็บรูปล็อต: `lot_photos(id, lot_id, path, created_at)` เก็บไฟล์ใน `server/uploads/` (ไม่ commit), เสิร์ฟผ่าน `/uploads/...`, jpeg/webp ไม่เกิน 1MB หลังย่อ; **รูปจากการประเมิน AI บันทึกเป็นรูปล็อตอัตโนมัติ** (คง `harvest_lots.photo_url` เป็นรูปหลักถ้ามี จนกว่าจะมีหลายรูป)
- `GET /api/public/market?lat=&lng=&radius_km=&crop_id=&sort=` ไม่ต้อง login, rate limit 60/นาที/IP
  - คืน: รูป, พืช, น้ำหนัก/คงเหลือ, เกรด, ความสุก, **`available_as`** (ไม่คืน `sale_mode`), **ราคาปัจจุบัน + ราคาตลาดอ้างอิง** (เมื่อ `available_as` เป็น `['donate']` อย่างเดียว ไม่แสดงราคา), เวลาที่เหลือ, ระยะทางปัดเป็น 0.5 กม. (ถ้ามี lat/lng), ชื่อพื้นที่แปลง (`plot_name` จนกว่าจะมีตำบล/อำเภอ — D022), ขั้นต่ำ/step/split, **สิทธิ์รับบริจาคของผู้ดู** (ถ้ามี token)
  - ไม่คืนพิกัด ชื่อผู้ขาย หรือข้อมูลติดต่อ
- `GET /api/public/lots/:id` รายละเอียดล็อตแบบเดียวกัน
- แอป: แท็บตลาดแสดง **grid การ์ดมีรูป** โดยไม่ต้อง login; ขอตำแหน่งเพื่อคำนวณระยะ ถ้าไม่ให้ใช้ LocationPicker หรือแสดงทั้งหมดเรียงตามเวลาที่เหลือ; ตัวกรองพืชและเรียง ใกล้สุด / ด่วนสุด / ถูกสุด
- กดจองหรือกด "ลงขาย" ตอนยังไม่ login → `/login?returnTo=` แล้วกลับมาที่เดิม
- **Done when:** เปิดแอปโดยไม่ login เห็นสินค้าพร้อมรูปและป้ายจาก `available_as` (ไม่มีแผนบริจาคล่วงหน้า), ล็อต donate-only ไม่มีราคา, response ของ public API ไม่มีพิกัด/`sale_mode`/ข้อมูลผู้ขาย (มี test ยืนยัน)

## 6.3 รายการพืชที่ขยายได้
- migration: `crop_categories(id, name_th, default_shelf_days, parcel_allowed)` เช่น ผักใบ 2 วัน/ไม่ส่งพัสดุ, ผลไม้เมืองร้อน 5 วัน, ผลไม้เปลือกแข็ง/ส้ม 14 วัน, หัว/ราก 21 วัน, สมุนไพร 4 วัน
- `crops` เพิ่ม `category_id`, `parcel_allowed`, `storage_tip_th`, `fridge_ok` (BOOL), `fridge_extra_days`, `status ENUM('approved','pending')`, `created_by` NULL, **`normal_features_th` / `defect_examples_th` จากค่าเริ่มต้นของหมวด**
- seed เพิ่มพืชที่พบบ่อยในไทยให้ได้ประมาณ 30 ชนิด พร้อมคำแนะนำการเก็บ; ค่าทุกตัวเป็นค่าประมาณที่บันทึกแหล่งอ้างอิงไว้ใน `docs/crop-sources.md` และให้ผู้ใช้ตรวจก่อน merge
- เกษตรกรเพิ่มพืชที่ไม่มีได้: ชื่อ + หมวด + ราคาตลาดปกติ/กก. → สร้าง crop `status = pending` ใช้ค่าเริ่มต้นของหมวดทันที การ์ดแสดงป้าย "พืชใหม่ รอตรวจ"; **จับคู่ DIT อัตโนมัติแบบเดียวกับพืชเดิม**; **ราคาตลาดที่เกษตรกรกรอกเป็นฐานกรอบ start/floor จนกว่าจะมีราคา DIT**
- ผู้ดูแลอนุมัติ/แก้ค่า/รวมกับพืชที่มีอยู่ได้ในหน้าผู้ดูแล
- แอป: chip พืชเปลี่ยนเป็นช่องค้นหา + รายการพืชที่ใช้บ่อยของผู้ใช้ + ปุ่ม "เพิ่มพืชใหม่"
- AI ประเมินรูปใช้ชื่อพืชจริงของล็อต (รวมพืชใหม่) ใน prompt
- **Done when:** ลงล็อตพืชใหม่ได้โดยใช้ค่าหมวดและ features เริ่มต้น, อนุมัติแล้วค่าอัปเดต, test shelf-life ของพืช pending

## 6.4 วิธีรับของ: มารับเอง หรือ ส่งพัสดุ
> ต่อยอดจากหน้า `/orders/:id` (6.1f) และหลายออเดอร์ต่อล็อต (6.1e) — **ยืนยันรับเป็นรายออเดอร์** ไม่ใช่ทั้งล็อต

- `harvest_lots.fulfillment_options` (pickup, parcel); parcel เลือกได้เฉพาะเมื่อ `crop.parcel_allowed` และเหลือเวลา > 72 ชม. ตอนลงขาย **และ** ตอนจอง
- **มารับเอง**
  - ตอนจอง (หน้า confirm) เลือกช่วงเวลามารับ (ต้องจบก่อนล็อตหมดอายุอย่างน้อย 2 ชม.)
  - หน้า "เส้นทางรับของวันนี้" ของผู้ซื้อ: รวม**ออเดอร์**ที่ชำระแล้วของวันนั้น จัดเส้นทางจากตำแหน่งผู้ซื้อด้วย `RouteSolver` เดิม เปิดแต่ละจุดใน Google Maps ได้
  - ส่งมอบบน `/orders/:id`: ผู้ซื้อตรวจของที่แปลง พอใจแล้วแสดง OTP → **ผู้ขายกรอก OTP และน้ำหนักจริงต่อออเดอร์** = ผู้ซื้อยอมรับของ; น้ำหนักต่างเกิน 10% ของ `quantity_kg` ต้องให้ผู้ซื้อกดยอมรับน้ำหนักใหม่ก่อน และปรับยอดเงินตามจริงด้วย**ราคาที่ล็อกไว้ตอนจอง** (คืนส่วนต่าง)
  - ผู้ซื้อปฏิเสธของที่แปลงได้ (เลือกเหตุผล + รูป) → เปิดข้อพิพาททันที
- **ส่งพัสดุ**
  - ผู้ซื้อกรอกที่อยู่จัดส่งตอนจอง; ค่าส่งเป็นอัตราคงที่ต่อ กก. × `quantity_kg` ตั้งใน config (บันทึกใน DECISIONS)
  - ผู้ขายกรอกเลขพัสดุไปรษณีย์ไทยต่อออเดอร์ → แอปแสดงลิงก์หน้าติดตามพัสดุ (ไม่เรียก API)
  - ผู้ซื้อกด "ได้รับของแล้ว" หรือเปิดข้อพิพาทภายใน 24 ชม.; ไม่ทำอะไรเลย ระบบถือว่ายอมรับเมื่อครบ 5 วันหลังผู้ขายกรอกเลขพัสดุ
- **ออเดอร์บริจาค: รับเองเท่านั้น (ไม่ส่งพัสดุ)**
- ย้าย `batches`/`route_stops` ให้ผูกกับผู้ซื้อ (`owner_user_id`) แทนโมเดลรอบวิ่งเก่า ผ่าน migration (ลบโค้ดหน้าจอรอบวิ่งเก่าใน 6.11)
- **Done when:** flow test มารับเองและส่งพัสดุต่อออเดอร์ผ่านครบ (รวมหลายออเดอร์บนล็อตเดียวกัน), parcel ถูกปฏิเสธเมื่อเวลาเหลือไม่พอหรือเป็นออเดอร์บริจาค

## 6.5 Escrow (sandbox)
- `PaymentProvider` interface: `createCharge`, `getStatus`, `refund`, `payout`; ทำ `MockPaymentProvider` (ค่าเริ่มต้น) และเผื่อไว้สำหรับ Opn/Omise test mode ผ่าน env ภายหลัง
- `payments(id, order_id, amount, status, provider, provider_ref, deadline_at, paid_at, released_at, refunded_amount)` — **หนึ่ง payment ต่อออเดอร์**; `amount` = `agreed_price_per_kg × quantity_kg` (+ ค่าส่งถ้ามี)
- สถานะ: `pending → paid_held → released | refunded | partially_refunded`, `pending → expired`
- `ledger_entries(id, order_id, account, debit, credit, memo, created_at)` บัญชี: buyer_cash, escrow_hold, seller_payable, refunds — ทุกการเปลี่ยนสถานะเงินบันทึกคู่ debit/credit ที่สมดุล (มี test ยืนยันยอดรวมเป็นศูนย์)
- เวลาชำระ (pure function ใน domain): `clamp(5% ของชั่วโมงที่เหลือ, 15 นาที, 2 ชม.)` และไม่เกินเวลาเริ่มช่วงนัดรับ
- **ออเดอร์บริจาคไม่มี payment** แต่มีกำหนดยืนยันช่วงนัดรับ; **ราคาที่ล็อกตอนจองมาจากสูตรที่มี floor**
- แอป: หลังจองแสดง QR PromptPay จำลอง + ปุ่ม "จำลองการชำระ" (เฉพาะ sandbox) + นาฬิกานับถอยหลังบน `/orders/:id` (ข้ามสำหรับบริจาค)
- ปล่อยเงินให้ผู้ขายเมื่อผู้ซื้อยอมรับของ (6.4); คืนเงินเมื่อยกเลิก/ข้อพิพาท
- หน้า "กระเป๋าเงิน" ของผู้ขาย: ยอดรอรับ, ยอดได้รับแล้ว, รายการย้อนหลัง
- เมื่อ payment หมดเวลา: คืน `quantity_kg` เข้าคงเหลือของล็อต (สถานะล็อตตาม 6.1e) ไม่จำเป็นต้องทั้งล็อตกลับ `open`
- **Done when:** ทุก transition ของ payment มี test, ledger สมดุลทุกกรณี, หมดเวลาชำระแล้วคงเหลือกลับ, ออเดอร์บริจาคไม่มีแถว payment

## 6.6 ความน่าเชื่อถือของการจอง
- ยกเลิกก่อนชำระ: ฟรี; หลังชำระก่อนนัดรับ: คืนเงินเต็ม แต่นับเป็น "ยกเลิกช้า"; ไม่มารับตามนัด (เลยช่วงนัด + 1 ชม.): คืนเงินเต็ม นับเป็น "ไม่มาตามนัด" และคืน `quantity_kg` เข้าคงเหลือ
- ผู้ขายยกเลิกหลังรับเงิน: คืนเงินผู้ซื้อเต็ม นับสถิติฝั่งผู้ขาย
- `waitlist(lot_id, user_id, quantity_kg, created_at)` — ผู้รอคิว**ระบุจำนวน กก. ที่ต้องการ**; เมื่อมีคงเหลือ (ยกเลิก/หมดเวลาชำระ/ลดน้ำหนักไม่เกี่ยวกับคิว) เสนอคนแรกในคิวที่ `quantity_kg` ≤ คงเหลือ ภายใน 15 นาที แล้วค่อยเปิดให้ทุกคน; ถ้าคงเหลือไม่พอคนแรก ให้ข้ามไปคนถัดไปที่พอดี
- **การสลับ `sell_then_donate` ต้องเคารพ waitlist** (คิวผู้ซื้อได้ก่อนถ้ายังมีเวลา)
- สถิติผู้ใช้ (คำนวณจาก orders): รับสำเร็จ, ยกเลิกช้า, ไม่มาตามนัด แสดงบนการ์ดคำสั่งซื้อฝั่งผู้ขาย; **แยกสถิติ "ไม่มาตามนัด" ออกจากการนับรูปยืนยันบริจาคของ 6.1b**
- ไม่มาตามนัดครบ 3 ครั้งใน 30 วัน → จองได้ครั้งละ 1 ออเดอร์ (บันทึกใน DECISIONS)
- expire job เดิมขยายให้ตรวจ payment หมดเวลา และนัดรับที่เลยเวลา
- **Done when:** test ครบทุกเส้นทางการยกเลิก, waitlist ตาม กก., sell_then_donate เคารพคิว, และ job

## 6.7 ปุ่มติดต่อ

- **Done when:** test ว่า API ไม่คืนเบอร์/LINE ก่อนชำระ/ก่อนยืนยันนัด

## 6.8 ข้อพิพาท
- `disputes(id, order_id, opened_by, reason, status, ai_summary, resolution, refund_amount, decided_by, created_at, decided_at)` + `dispute_photos`
- สถานะ: `open → ai_reviewed → resolved_refund | resolved_partial | resolved_release`
- ผู้ซื้อเปิดได้: ตอนปฏิเสธที่แปลง หรือภายใน 24 ชม. หลังได้รับพัสดุ; ต้องแนบรูปอย่างน้อย 1 รูป
- AI (ใช้ vision client เดิม) เทียบรูปล็อตกับรูปหลักฐาน → สรุปความต่างเป็นภาษาไทย + ระดับความรุนแรง; **AI ไม่คืนเงินเอง**
- หน้าผู้ดูแล: รายการข้อพิพาท, รูปทั้งสองฝั่ง, สรุป AI, ปุ่มตัดสิน (คืนเต็ม / คืนบางส่วน / โอนให้ผู้ขาย) + เหตุผล
- ระหว่างข้อพิพาท เงินอยู่ใน escrow
- **ออเดอร์บริจาคไม่มีการคืนเงิน** — ข้อพิพาทเป็นการรายงานคุณภาพ มีผลต่อสถิติผู้ขาย
- **Done when:** flow test ทั้งสามผลตัดสิน (ซื้อ), รายงานคุณภาพบริจาค, ledger สมดุล, AI ล้มเหลวแล้วยังตัดสินได้

## 6.9 คำแนะนำหลังรับของ
- เมื่อผู้ซื้อยอมรับของ แสดง "ควรขาย/รับประทานภายใน X (ถึงวัน-เวลา)" จาก `expires_at` ของล็อต

- เก็บไว้ในหน้า "ของที่ได้รับ" ดูย้อนหลังได้
- **Done when:** คำนวณใน domain มี test, ข้อความไม่ได้มาจาก AI สร้างสด
